# CPU-only build of PyTorch: this machine has no CUDA device, and the training
# run is small enough that CPU inference is comfortably fast.
#
# Install with:
#   uv pip install --python .venv/bin/python -r requirements.txt \
#     --index-url https://download.pytorch.org/whl/cpu
#
torch>=2.14

# torch's NumPy interop is decided at import and stays off when numpy is absent.
# `torch.from_numpy` then raises at the call site instead of here, and the only
# warning is a "Failed to initialize NumPy" line at import that reads like
# noise. Nothing in this repo imports numpy today, so a missing one is invisible
# until the first ad-hoc conversion -- which is how a rebuilt venv ended up with
# a torch that could not do this. Listed explicitly rather than left to arrive
# as a dependency: the CPU index's torch wheel does not declare it. The index
# does mirror numpy's own wheels, so the install above carries it too.
numpy>=2.5

# set (numpy, requests) but not everything on PyPI -- archil's path there
# answers 403, and a package the index does not carry fails the whole install,
# which is what CI found. The tests workflow installs that file from PyPI,
